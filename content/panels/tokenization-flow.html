03 · Tokenization — Flow

From Detector Numbers to Embedded Vectors

A transformer does not read numbers; it reads tokens — integer IDs drawn from a fixed vocabulary, each mapped to a learned vector by an embedding table. Both a page of text and a table of continuous detector features must arrive at that same destination. The destination is identical; the route is nearly opposite. This panel lays out both routes and where HELIX's data joins them.

The shared destination

Whatever the source, an embedding layer eats exactly one thing: a sequence of integer token IDs from a finite vocabulary of size $V$. The embedding table is a lookup — row $i$ is a learned vector for token $i$. So every pipeline must produce (a) a fixed vocabulary, and (b) each input as an ordered list of IDs in $[0, V)$. Vectorization — learning those rows — is mechanically the same for text and for detector features; only the meaning of a row differs.

source → TOKENIZE → integer IDs → EMBED → vectors → transformer

Route A — continuous detector features

Detector data arrives dense, continuous, and ordered — real magnitudes, no natural symbols. Tokenization here is a quantization problem: you must manufacture the symbols. Four steps take a CSV value to an honest token:

  1. Bin — and freeze the edges. Binning splits each feature's range into intervals and replaces a value with its interval index. Edges are fit once on a training set and reused everywhere, so a token means the same value-range in every sample.
  2. Namespace into one vocabulary. Each feature bins to $0\ldots\text{N}_\text{bins}-1$ independently, so codes collide across features. Offset each feature into its own block (feature 0 → $0\ldots15$, feature 1 → $16\ldots31$, …) so every ID is globally unique and means one (feature, bin) pair.
  3. Add structural tokens. Zero-inflated and integer-count features need explicit handling: a dedicated zero token, native tokens for small-integer counts, and reserved missing / out-of-range tokens. (Which features need this is read straight off the occupancy metrics.)
  4. Order into a sequence. An event is a set of features; a transformer needs an order. HELIX uses the causally-ordered cutflow sequence, with a feature/position tag so the model knows what each slot is.

Route B — a text corpus

Text arrives already discrete and symbolic. There is nothing continuous to bin; tokenization is a segmentation + vocabulary problem. Sub-word schemes (BPE / WordPiece) build the vocabulary from corpus frequency — merge the most common character pairs until a target size is reached — then map each unit to an ID by dictionary lookup. The vocabulary is one shared set, order is the natural reading order, and a token ID is purely nominal: token 4012 has no magnitude.

The vectorization step, and why HELIX's case is richer

Both routes feed an embedding table and learn vectors the same way — but the opportunity differs. Text IDs start meaningless, so the embedding must learn all structure from co-occurrence alone. HELIX's tokens are ordinal: bin 7 really is larger than bin 3. A naive lookup table throws that away, treating adjacent bins as unrelated symbols; numeric-aware embeddings (piecewise-linear / periodic) preserve the ordering you worked to keep. This is the open design choice at the Evt2Vec stage: embed bins nominally (simple) or numeric-aware (preserves magnitude).

The bonus text never gets. A HELIX token is not an arbitrary symbol — it is “feature F is in value-range R.” So a learned vector can be checked against physics: do adjacent value-bins sit near each other, do high-displacement bins cluster with signal? Text embeddings can only be validated relationally; HELIX embeddings can be validated against known physical ordering.

Scope note: the discretization gate validates only the first step — that binning preserves a feature's label information. Steps 2–4 (namespacing, structural tokens, ordering) and the embedding choice are built at the Evt2Vec / CutFormer stage. “We proved we can tokenize” is not yet “we have a tokenizer.” See the Metrics panel for how that first step is measured, and the Journey panel for current results.
